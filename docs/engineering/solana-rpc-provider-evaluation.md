# Solana RPC Provider Evaluation and Selection

**Research date:** 2026-11-20
**Status:** Provisional engineering evaluation for M3. This document selects no provider as an implementation fact and does not claim endpoint correctness or production reliability.

## Purpose and workload

Compare Chainstack, QuickNode, Helius, Alchemy, and Triton One for a deliberately small read-only workload:

- Solana JSON-RPC over HTTPS.
- `getGenesisHash` followed by `getSlot` with commitment `finalized` to verify network identity and observe the slot.
- Low-frequency calls, with two standard RPC calls per observation when network identity is checked on each call.
- Predictable client-side timeout and error handling; low or zero monthly spend.
- No streaming, indexing, archive history, transaction submission, or dedicated node requirement.

Solana's HTTP RPC reference defines JSON-RPC 2.0 POST requests; `getGenesisHash` returns the genesis hash and `getSlot` accepts a commitment and returns a `u64` slot. The example explicitly uses `finalized`. These are standard Solana methods, not provider-specific features ([Solana HTTP methods](https://solana.com/docs/rpc/http), [`getSlot`](https://solana.com/docs/rpc/http/getslot), [`getGenesisHash`](https://solana.com/docs/rpc/http/getgenesishash)).

## Operational criteria

| Criterion | Findings and limits of evidence |
| --- | --- |
| Timeout and errors | Solana defines request/response semantics, not a client timeout or provider latency guarantee. QuickNode documents authentication, rate-limit, HTTP 429/503, and method-limit errors; Alchemy documents HTTP status and JSON-RPC error handling; Triton publishes common 429/5xx and JSON-RPC error guidance. Chainstack's plan limit does not define a per-call deadline. No provider-specific timeout guarantee for these two small reads was verified. The adapter should own an explicit timeout and map transport/HTTP/JSON-RPC failures to the existing `ObservationError`. [QuickNode errors](https://www.quicknode.com/docs/solana/error-references), [Alchemy errors](https://www.alchemy.com/docs/reference/error-reference), [Triton errors](https://blog.triton.one/triton-rpc-error-codes-troubleshooting-guide-faq-for-developers/) |
| Asia-Pacific | Chainstack operates Global Nodes with geo-balanced routing; its published vendor benchmark included a Singapore probe. QuickNode describes global load balancing, but selectable Solana endpoint regions were not established. Helius describes global edge routing and its live benchmark includes AP-Northeast/AP-Southeast, but that is not a latency promise. Alchemy's selectable Solana RPC region is unknown; a Helius-run snapshot included Singapore results. Triton advertises global bare-metal/GeoDNS routing; specific standard-RPC region selection is unknown. For this project, compare observed Indonesian/nearest-region smoke-test latency rather than infer it from a vendor region map. [Chainstack nodes](https://chainstack.com/), [Chainstack benchmark](https://chainstack.com/reports/node-infrastructure/solana-rpc-provider-benchmark-latency-and-uptime-november-2026/), [QuickNode endpoints](https://www.quicknode.com/docs/solana/endpoints), [Helius Gatekeeper](https://www.helius.dev/blog/introducing-gatekeeper), [Helius benchmark](https://www.helius.dev/benchmarks), [Triton pricing](https://www.triton.one/pricing/) |
| Credential and endpoint security | Treat each RPC endpoint as a secret: Chainstack, QuickNode, Helius, and Alchemy commonly encode credentials in endpoint paths or URLs. Keep endpoint values out of source control, logs, exception text, and command output. QuickNode documents URL-token and header-token options plus endpoint restrictions. Exact authentication options depend on provider and plan; confirm whether a header-based credential is supported before implementation. [QuickNode security](https://www.quicknode.com/docs/solana/endpoint-security), [Alchemy endpoints](https://www.alchemy.com/rpc/solana), [Chainstack authentication](https://docs.chainstack.com/docs/authentication-methods-for-different-scenarios), [Triton pricing/onboarding](https://www.triton.one/pricing/) |
| Portability and lock-in | JSON-RPC 2.0 method names, request shape, and standard `getSlot`/`getGenesisHash` behavior are portable. Endpoint format, authentication, billing units, quotas, throttling rules, dashboards, and vendor-specific extensions are not. Keep provider details in endpoint configuration and the adapter boundary; do not add vendor extensions to M1 domain models. |
| Reliability evidence | Published uptime, latency, and “high performance” statements are vendor claims unless independently measured. They are not guarantees for this project's endpoint, free plan, region, or exact method mix. Use smoke-test results only as a selection gate, not a production SLO. |

## Published limits and benchmark caveats

1. **Chainstack distinct plan and network limits:** the Developer Free plan card lists 25 requests/s as a general plan limit. Chainstack's Solana-specific docs separately state 5 RPS for Solana Mainnet Developer and 25 RPS for Solana Devnet Developer. These figures apply at different scopes; do not collapse them into one limit. Neither required method is listed as having a separate published cap. Both official sources reviewed **2026-11-20**. [Plan card](https://chainstack.com/pricing/), [Solana throughput](https://docs.chainstack.com/docs/limits).
2. **QuickNode method rules:** the trial's 15 RPS is plan-level. Method-level limits can be configured separately, and a documentation example's custom 1/minute `getSlot` cap is not evidence of a provider default. API credit cost and request rate are separate measures. [Pricing](https://www.quicknode.com/pricing), [method-limit guide](https://www.quicknode.com/guides/quicknode-products/endpoint-security/how-to-setup-method-rate-limits).
3. **Alchemy published-value conflict (reviewed 2026-11-20):** the official pricing page's indexed snapshot showed Free at 25 RPS, while its directly rendered page showed 15 RPS. These are request-rate figures, distinct from CU/s throughput and the 30M CU/month allowance. The pricing-plan page specifies $0.525/M CU and Free/PAYG base throughput of 300/10,000 CU/s; the marketing pricing page displays $0.52/M CU and PAYG starting from 300 requests/s. The throughput guide and currently rendered Free-tier support article show 300 CU/s; an older support-article version dated 2026-08-25 reported 500 CU/s. Do not convert CU/s to RPS or treat 500 CU/s as 500 RPS. Verify the applicable account limits and price before selection. [Pricing](https://www.alchemy.com/pricing), [throughput](https://www.alchemy.com/docs/reference/throughput), [pricing plans](https://www.alchemy.com/docs/reference/pricing-plans), [Free Tier support article](https://support.alchemy.com/articles/5827006872-what-is-included-in-the-free-tier).
4. **Triton pricing/limit uncertainty (reviewed 2026-11-20):** official pricing evidence conflicts: indexed official-page material states a $125 prepaid minimum, while the page directly rendered in this review displayed $25. Both state prepaid, non-refundable funds valid for 12 months. No active minimum is asserted here; confirm the amount in checkout. The FAQ lists questions about trial and rate limits, but reviewed content did not include answers; trial duration and default/method-specific limits remain unknown. [Pricing](https://www.triton.one/pricing/).
5. **Chainstack vendor benchmark:** the Nov 2026 report covers a 7-day window, Nov 5 14:06 UTC–Nov 12 14:06 UTC, probes from DE/US/SG every 1–3 minutes, and selected plans (QuickNode Growth, Helius Developer, Alchemy Growth, first paid plan for Chainstack). It did **not** test `getSlot` or `getGenesisHash`, and its own disclosure says Chainstack operates the probes, dashboard, and scoring formula while also being ranked. The reported SG result (Chainstack P95 40 ms) is vendor-produced evidence for a different plan/method mix, not independent verification or a result for Developer Free. [Benchmark and methodology](https://chainstack.com/reports/node-infrastructure/solana-rpc-provider-benchmark-latency-and-uptime-november-2026/).
6. **Helius benchmark:** the live benchmark is operated by Helius, changes over time, and reports the methodology/window on its page. It can inform which regional tests to run, but its rankings and scores are not an independent reliability guarantee. [Benchmark](https://www.helius.dev/benchmarks), [methodology](https://www.helius.dev/blog/how-we-benchmark-rpc-performance).

## Provisional recommendation

Use **Chainstack Developer Free** as the preferred first live-adapter candidate, subject to an endpoint smoke test. The documented free plan and standard Solana HTTPS JSON-RPC fit low-frequency reads; use the Solana-specific 5 RPS Mainnet limit rather than the general 25 RPS plan figure. Verify both required methods, finalized commitment behavior, genesis hash, endpoint credential handling, timeout/error behavior, and observed latency from the project's deployment region before implementation is considered ready.

Keep **QuickNode** as the primary comparison/fallback candidate. Its method pages, free-trial limits, and method-credit table are explicit, but the trial lasts one month and custom method controls must not be mistaken for provider defaults.

This is a provisional engineering recommendation only. No account was created, no credential obtained, no endpoint smoke test run, and no claim is made about live correctness or production availability.

## Selection gates and unresolved decisions

Before provider selection is final:

- Run the same read-only HTTPS smoke-test sequence against candidate endpoints from the intended region; record status, JSON-RPC shape, genesis hash match, finalized slot result, latency, and observed failure handling without recording endpoint secrets.
- Confirm plan-specific monthly allowance, provider-native unit cost for both methods, method-level limits, free-tier duration, and overage behavior in the actual account dashboard/terms.
- Confirm whether the provider's standard endpoint returns expected values for both calls and whether the endpoint routes to mainnet.
- Choose timeout budget and document the resulting two-request total deadline.
- Choose how endpoint credentials are stored and rotated without adding them to logs or source control.
- Decide whether freshness or source health objectives are needed; M1/M2 define no SLO.
- Revisit the recommendation if zero prepaid cost, regional latency, endpoint security controls, or verified limits outweigh the initial fit.
